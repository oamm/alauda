# Alauda v0.2.0

Docker Hub image: `oamm/alauda:0.2.0` (also tagged `oamm/alauda:v0.2.0`). The image includes the registry server, the web console, and the `alauda` CLI.

- Reuse the name of a deleted service. The new service gets a new ID, and historical data stays with the deleted ID.
- Configure PostgreSQL or SQLite storage. PostgreSQL is the default. Set `ALAUDA_STORAGE_PROVIDER=sqlite` and the existing database file path explicitly when upgrading a SQLite installation.
- Define HTTP, HTTPS, gRPC, PostgreSQL, Redis, TCP, UDP, and custom endpoints in the console and public API. The API now uses `kind` in place of `protocol`; deploy the matching CLI and update callers that send or read the old field. Only HTTP and HTTPS endpoints accept a path.
- Use the Security workspace to manage user access and scoped credentials.

## Docker upgrade

1. Record the active image digest, ports, network settings, environment and secret sources, and persistent mounts. Pull `oamm/alauda:0.2.0` before stopping the current container.
2. Back up the existing storage and verify that the backup restores to a separate target. For PostgreSQL, use `pg_dump -Fc` and restore into a separate database with `pg_restore --exit-on-error`. For SQLite, use the SQLite backup API or copy the database and its WAL and shared memory files together while the app is stopped.
3. Schedule a short maintenance window. Stop all Alauda instances writing to the database and take a final backup. Start the new image with the same database connection, mount paths, and Docker settings. Alauda applies migrations at startup.
4. Check `/readyz`, confirm the reported version, sign in, and check that existing services and health history are present. Keep the old container and the final backup until validation is complete.

If a migration has already run, rehearse any downgrade against a restored copy before starting the old image. A database restore reverts writes made after the backup. Service names reused after this upgrade can prevent reinstating the former global uniqueness constraint.
